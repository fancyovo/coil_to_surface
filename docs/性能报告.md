# 性能报告

本文记录当前主线的性能结构和已知瓶颈。具体耗时强依赖 GPU、CPU、CUDA 版本、Simsopt 版本、线圈复杂度和候选磁面的数量，因此这里重点说明计时口径、阶段含义和优化结论。

## 1. 计时字段

每次评估会在 `summary.json` 的 `timing` 字段中输出细粒度耗时。常用字段如下：

| 字段 | 含义 |
| --- | --- |
| `field_build_s` | 构造线圈、周期复制和 Python 侧磁场对象的时间。 |
| `axis_s` | 磁轴阶段总时间。 |
| `axis_search_s` | 固定点网格追踪、候选提取、Newton 修正和复核。 |
| `axis_trace_s` | 找到轴点后沿磁轴追踪并采样一个周期。 |
| `axis_topology_s` | 椭圆/双曲拓扑筛耗时。 |
| `psi_fit_s` | $\psi$ 拟合总时间。 |
| `psi_training_point_s` | 构造训练/验证采样点。 |
| `psi_B_sample_s` | 在采样点上计算 $\mathbf{B}$。 |
| `psi_assemble_s` | 组装 $\mathbf{B}\cdot\nabla\psi$ 线性系统。 |
| `psi_qr_factor_s` | QR 分解主耗时。 |
| `psi_qr_apply_qtb_s` | 计算 $Q^T b$。 |
| `psi_qr_tri_s` | 上三角回代。 |
| `psi_validation_s` | 验证集残差计算。 |
| `surface_screen_s` | $\psi_0$ 候选筛选总时间。 |
| `surface_screen_curve_newton_s` | 每个 $\psi_0$ 上等值曲线 Newton 求解。 |
| `surface_screen_fieldline_trace_s` | 从等值曲线起点批量追踪一个周期。 |
| `surface_screen_verify_trace_s` | 对少数候选做高精度复核追踪。 |
| `surface_extract_1d_newton_s` | 候选磁面点云提取的一维 Newton。 |
| `surface_extract_coeff_build_s` | GPU 面提取所需系数准备。 |
| `surface_extract_copy_in_s` | 面提取输入拷贝到 GPU。 |
| `surface_extract_copy_out_s` | 面提取结果拷回 CPU。 |
| `boozer_ls_s` | Simsopt Boozer least-squares 步。 |
| `boozer_newton_s` | Simsopt Boozer Newton 步。 |
| `boozer_qs_s` | QS error 计算。 |
| `boozer_candidates_s` | 所有 Boozer 候选面的总时间。 |

批量脚本 `scripts/eval_quasr.py` 会把这些字段展开到 `batch_summary.csv`，列名前缀为 `timing_`。

`quality_score` 当前没有单独计时字段，因为它是末尾的轻量后处理。主要开销是线圈工程项的曲线采样、曲率计算和 KDTree 最近邻查询；相对 GPU 磁力线追踪、$\psi$ 拟合 QR 和 Boozer 阶段通常不是瓶颈。若后续在超大规模数据集上只做工程项筛选，可以单独给 `coil_geometry_metrics` 增加计时。

## 2. 当前默认设置

默认配置偏向 GPU 批量执行：

- 磁轴：固定点网格 + 小批量 Newton + 高精度复核 + 椭圆拓扑筛。
- 磁力线追踪：`mixed64`，即磁场贡献主要用 `fp32`，轨道推进保留双精度状态。
- $\psi$ 拟合：GPU 端采样、组装和 QR 求解，`linear_solver=qr`。
- $\psi_0$ 筛选：GPU 批量追踪一个周期。
- 等 $\psi$ 面提取：GPU 批量一维 Newton。
- Boozer/QS：仍主要依赖 Simsopt 的 CPU/Python 路径。

CPU 线程默认设为 1。对于小批量 `.B()` 或 Simsopt 调用，OpenMP 多线程同步开销经常大于实际计算收益；批量足够大时才应重新测试多线程。

## 3. 主要瓶颈

### 3.1 $\psi$ 拟合

$\psi$ 拟合通常是最大单项耗时。它包括：

1. 在局部体积内生成训练点。
2. 对所有点计算 $\mathbf{B}$。
3. 组装线性系统。
4. 求解最小二乘。
5. 在验证点上计算无量纲角度残差。

早期实现中，瓶颈主要来自磁场采样和 CPU/GPU 间传输；当前主线已经把采样、组装和 QR 主要放到 GPU 上，CPU 只接收最终系数和统计量。

QR 默认取代法方程。原因是法方程需要形成 $A^T A$，条件数会平方放大；即使矩阵乘法可用 `fp32` 加速，病态问题仍可能放大误差。QR 更稳健，通常是当前推荐默认。

### 3.2 磁力线追踪

磁力线追踪出现在三个地方：

- 磁轴固定点搜索：大量起点同时追踪一个周期。
- $\psi_0$ 筛选：每个等值曲线起点追踪一个周期。
- 高精度复核：少量候选用更高精度重新追踪。

GPU kernel 目前采用“一条线一个 block”的方案。相比“一条线一个 warp”，block 级并行能让更多线程共同计算单点磁场，对当前电流元规模更合适。

磁场计算的理论瓶颈不是单纯显存带宽。每个电流元贡献包含平方根、倒数幂等特殊函数和较多双/单精度浮点运算；在 `fp64` 下更容易受双精度吞吐限制，在 `mixed64`/`fp32` 下特殊函数和指令吞吐仍是重要限制。

### 3.3 Boozer/QS

Boozer 阶段不是当前 GPU 化最充分的部分。它包含：

- 初始 surface 拟合。
- Simsopt least-squares。
- Simsopt Newton。
- QS error 积分/采样。

在单个候选面上，LS/Newton 本身有时很快；但如果候选面数量增加或初始面质量差，Boozer 阶段会成为主要尾部耗时。因此默认只对通过 $\psi_0$ 筛选的最大少数候选做 Boozer。

## 4. 已完成的优化

### 4.1 磁轴搜索

早期遗传算法会保留 top 点并反复组合，适合并行但容易被崎岖 landscape 和双曲周期点误导。当前固定点方法先在全局网格上找绕数和局部极小，再对候选做 Newton，通常更稳定。

新增拓扑筛后，闭合但双曲的周期点不会默认被当作磁轴。该筛选代价相对磁力线追踪很小，主要增加少量有限差分追踪和矩阵分类。

### 4.2 $\psi_0$ 筛选

筛选阶段只追踪一个周期，不做长时间场线积分。目标是快速判断某个 $\psi_0$ 的等值面是否局部闭合、是否在半径范围内、是否有合理漂移。这样可以避免对明显不可信的 level 做 Boozer。

### 4.3 等值面提取

早期逐点扫描和标量求根会让 `surface_extract_1d_newton_s` 明显偏大。当前默认 GPU 批量一维 Newton，把同一个 surface 网格上的所有点一起迭代，只把最终点云传回 CPU。

### 4.4 $\psi$ 线性求解

当前默认使用 GPU QR。它避免了法方程的条件数平方问题，并减少了 CPU/GPU 往返。`normal_eq` 路径仍保留，适合做速度/精度对比。

## 5. 批量评估参考

一次 1000 个随机 QUASR-like 位型的烟测结果如下，用于说明当前流程的稳定性和量级。该结果只应作为硬件相关参考，不应视为固定基准。

| 状态 | 数量 |
| --- | ---: |
| `surface` | 801 |
| `no_surface` | 134 |
| `no_axis` | 65 |
| chunk failed | 0 |

总运行时间约 55 分钟，使用单张高端消费级 NVIDIA GPU。该测试说明：

- 改进后的磁轴搜索已能显著减少 `no_axis`，但仍不会强行接受拓扑不合格的闭合点。
- 剩余失败主要集中在 `no_surface`，需要进一步区分 $\psi$ 拟合质量不足、$\psi_0$ 筛选失败和 Boozer 阶段失败。
- 批量评估应持续记录 `validation_angle_*`、`end_distance_p95`、`rel_end_distance_p95` 和 Boozer residual，不能只看最终状态。

## 6. GPU 优化建议

后续最值得继续优化的方向：

1. 继续减少 $\psi$ 拟合中的临时数组和拷贝，特别是 QR 前后的矩阵布局转换。
2. 对批量磁力线追踪做自适应 batch，避免小批量 kernel launch 或 CPU/GPU 同步开销。
3. 把 Boozer 前的 surface 拟合和部分残差评估继续 GPU 化。
4. 对失败样本采用分层策略：先看 axis topology，再看 $\psi$ angle，再看一周期漂移，最后才进入 Boozer。

不建议优先优化的方向：

- 对少量点的 `.B()` 调用盲目开启大量 CPU 线程。
- 为所有 $\psi_0$ 都跑完整 Boozer。
- 默认使用纯 `fp32` 追踪替代 `mixed64`，除非只做粗筛并有后续高精度复核。

## 7. 复现实验建议

公开仓库不包含大型数据集。复现实验时建议：

```bash
python -m stellarator_eval.cli \
  --case-file examples/01.json --key raw \
  --output-dir runs/01_raw
```

批量数据集评估：

```bash
python scripts/eval_quasr.py \
  --quasr-root /path/to/quasr/data \
  --metadata /path/to/metadata.csv \
  --sample-size 100 \
  --sample-seed 1 \
  --output-dir runs/quasr_smoke
```

比较不同配置时，应至少记录：

- 总耗时和 `timing_*` 分解。
- `axis.best_residual`、`axis.topology_class`、`axis.topology_ellipse_aspect`。
- $\psi$ 的 `validation_angle_mean/p95/l2`。
- 最大通过筛选的 $\psi_0$。
- Boozer 初始 residual、LS residual、Newton residual。
- QS error 和体积。

## 8. 诊断图耗时说明

`--export-axis-heatmap` 和 `--export-psi-slices` 是人工诊断功能，不属于默认性能基准。

`axis_residual_heatmap.png` 会额外对 `axis_heatmap_grid^2` 个点追踪一个场周期。若 `axis_heatmap_grid=512`，就是 262144 条一周期轨道；这一步非常适合 GPU，但会显著增加单样本耗时，因此不建议在大规模批量评估中默认开启。

`psi_slices.png` 主要是 CPU 侧 $\psi$ 多项式评估和 matplotlib 绘图。它不需要重新采样磁场，通常远轻于 axis heatmap，但高 `psi_slice_grid` 和高 `psi_slice_phi_count` 仍会增加内存与绘图时间。

建议口径：

- 做吞吐测速时不要开启诊断图。
- 调试单个失败样本时开启诊断图。
- 需要比较 axis 搜索算法时，固定 `axis_heatmap_grid` 后单独记录导图耗时。
