# 阶段技术报告与开源版本整理计划（第一版）

这份计划的目标不是把过去所有工作汇编成流水账，而是围绕一个可验证的核心结论组织材料：

> 我们实现了一条从 Fourier 线圈到物理诊断量、快速评分和 QH 优化的固定预算 GPU 路线；快速体指标能够有效指导优化，但最终磁面与平衡仍由 Simsopt/DESC 独立验收。

报告只保留支撑这句话所需的方法、实验和限制。失败探索一般不进入正文；只有当它明确界定方法边界时，才用一两句话说明。

## 对初稿框架的调整

初稿的 Methodology / Experiments 主体方向正确，但正式写作前需要补上三点：

1. 先明确研究问题和可声称的贡献，否则方法与实验容易变成并列罗列。
2. “三种评分模式”需要重新命名和定义。建议使用**独立评估**、**严格续接评估**和**近邻批量代理**。独立评估只有线圈输入，从零搜索磁轴；严格续接评估给出上一中心的磁轴状态，只允许在同一分支附近求解；近邻批量代理给出已完整评估的中心，批量评价小邻域候选，用于有限差分和局部排序。第三种不是与前两种等价的“完整 score 模式”，也不宜简称 `batch`，因为前两种同样可以批处理。它应单独标明近邻假设、复用量、近似量，以及更新后必须由正式评估验收。
3. 增加“适用范围与不能声称什么”。尤其不能把三维 $\alpha/\iota$ 拟合称为机器精度 Boozer 坐标，也不能把快速 score 当作磁面或 MHD 平衡证书。

## 技术报告的整体叙事

报告正文控制在六个主要部分，不继续拆成大量短小标题。

**1. 问题、目标和贡献。**

用一页左右讲清楚传统磁面求解为什么不适合作为大规模黑箱优化内环，以及本项目选择的折中：用固定预算三维拟合得到稳定、可批量的物理代理，再对少数候选运行标准磁面与 DESC。

贡献只总结三项：GPU 原生的线圈到体诊断链路；面向不同使用场景的独立/续接/近邻接口；Flow Matching 重参数化加有限差分 Adam 的优化方法。

**2. 从线圈到可解释诊断量。**

按物理依赖顺序连续说明：磁场与磁轴、几何不变量 $s$、磁通标定 $\psi(s)$、直场线坐标 $\alpha$ 与径向 $\iota(\rho)$、体 QA/QH/QP 和线圈工程量。每个新符号第一次出现时给出定义、输入、输出和数值求解方式，不使用未定义简称。

这一部分同时列出一次评估真正返回的元数据，并按“直接计算量、拟合诊断量、经验代理、状态/耗时”分类。总分只是这些元数据上的默认映射，精确权重与门函数放附录。

**3. 三种执行方式与优化循环。**

先用一张对照表定义三种方式各自需要的输入、重新计算的量、允许复用的量、输出和适用范围，再说明 Flow Matching 的架构、可逆 ODE 映射和潜空间 Adam。

优化循环的重点是：差分端点使用严格续接或近邻批量代理；每次更新后的中心必须使用正式评分；出现磁轴分支丢失时拒绝该步而不是切换磁轴。Flow 的作用表述为“改善搜索坐标”，不表述为“直接生成高质量线圈”。

**4. 方法是否有效。**

这一部分用现有 309 条轨迹作为主证据，比较随机 Flow 候选、32 选 1 起点、Adam 最优点和 QUASR QH 样本。主要展示：

- 分数分布和成功率如何变化；
- 200 步内分数与体 QH 的分位带；
- 不同 $N_{\mathrm{FP}}$ 和线圈数的覆盖情况；
- 工程分量是否因 QS 优化而系统性受损；
- 一个代表性高分样本的线圈、磁面、Boozer $|B|$ 等高线和 DESC 结果。

这里不把 309 条轨迹写成“所有条件均已解决”。报告会明确它们来自 QH 训练分布，且 200 步通常尚未完全收敛。

**5. 快速指标为什么可信、速度有多快。**

可信度部分以 96 条轨迹、8 个阶段、768 个位形和 1536 个标准面为主体。它回答四个具体问题：

- $\psi$ 的独立法向误差有多大；
- GPU $\iota$ 与标准面 $\iota$ 相差多少；
- 体 QH、外层壳层 QH 与 Simsopt 面 QH 的排序关系；
- $\alpha+\nu$ 初值与最终标准面的残差还差多少。

“可信”不作为空泛评价。每个量都指定参考值、误差定义、样本数、P50/P95 或相关系数，并说明哪些量没有可用真值。

性能部分在同一张空闲 RTX 5090、同一代码版本和同一批样本上重测三种执行方式，统一报告 P50/P95、失败率和阶段耗时。近邻批量代理还要给出 batch size 与单候选均摊时间，并以它对严格续接结果的局部排序相关性或方向一致性说明速度换来了什么误差。

**6. 结论、限制和复现。**

结论只回答开头提出的问题。限制集中写明 QH 数据范围、快速体代理与标准面的差别、score 的主观性、Flow checkpoint 的分布边界，以及为什么最终候选仍需完整物理验收。

附录保存默认 score 公式、全部超参数、JSON 字段、硬件环境、数据抽样规则和复现命令。这样正文保持可读，同时关键细节并不缺失。

## 需要补做或重新统一的实验

现有材料大部分可以复用，但以下两项不能直接拼接旧报告中的数字：

1. **三种执行方式的统一 benchmark。** 历史数字来自不同分支、不同 score 设置和不同节点状态。需在当前拟开源快照上使用同一批 QUASR 高质量样本、单张空闲 RTX 5090 重测，并保存逐阶段计时和状态。
2. **当前 score 下的 Flow 必要性。** 现有原空间/潜空间对照只有一个主起点，旧 landscape 又未必对应当前连续 score。建议选取跨早期、中期、高分阶段及不同条件的少量共同起点，做配对短程优化；主要比较相同墙钟下的体 QH、正式 score、无效端点率和最终独立复评。若旧 landscape 与当前 score 不一致，则重跑一个紧凑版本，否则只把它作为历史定性证据。

其余实验优先复用已经冻结的 309 条轨迹、768 位形标定和完整评估产物，不为了增加篇幅重复计算。

## 开源版本的整理方式

不建议大规模重写目录。现有 `gpu_backend/`、`stellarator_eval/`、`flow_matching/` 和 `evaluation/` 基本合理，重点是增加稳定的用户入口并清理实验接口。

**对外接口。**

- 提供一个统一 `Evaluator`，输入为线圈、$N_{\mathrm{FP}}$ 和配置，输出为结构化 `EvaluationResult`。
- 独立评估与严格续接评估属于正式接口；近邻批量代理使用单独的 `NeighborhoodEvaluator`，避免用户误以为三者给出完全等价的 score。
- 结果内部使用类型化对象和数组，保存时统一导出 JSON。字段必须包含配置、状态、磁轴、$s/\psi$、$\alpha/\iota$、QA/QH/QP、工程量、默认 score 分量和逐阶段耗时。
- 将“物理元数据计算”和“如何合成总分”分开。提供默认 `ScorePolicy`，同时允许用户传入自定义策略；优化热循环使用向量化策略，避免逐候选 JSON 序列化。
- CLI 保留三个直接任务：单样本评估、批量评估、潜空间优化。完整 Simsopt/DESC 验收仍是独立命令，不能被默认 score 隐藏。

**文档和示例。**

公开仓库只保留三层文档：简短 README、这份技术报告、API/复现说明。方法细节并入技术报告或 API 说明，不再同时维护多份内容重复且容易不一致的长文档。

示例至少覆盖：独立评估、带续接的局部优化、自定义 score 策略、对一个结果运行完整磁面验收。每个示例都使用同一份小型输入并给出预期 JSON 字段，而不是只展示命令能启动。

**代码与发布边界。**

- 从私有主线逐项核对后迁移已验证实现，不整分支复制；失败的解析梯度、BOBYQA/BFGS、QA 样本外实验和集群脚本不进入公开运行路径。
- 近邻批量代理若统一验收尚未完成，先放在 `experimental` 命名空间，并在文档中写明近邻假设；不能为了让功能表更丰富而伪装成稳定接口。
- 增加 JSON schema、配置回读、独立/续接一致性、磁轴分支拒绝、近邻排序和 CUDA smoke 测试。无 GPU 的 CI 运行纯 Python 测试；GPU 数值验收固定记录动态库、checkpoint 和数据摘要的哈希。
- 发布前扫描私有路径、服务器信息、Slurm 配置和不可再分发数据。Flow checkpoint 是否随版本发布必须单独核对 QUASR 数据许可；若不能发布权重，README 必须明确 score 可独立使用，并提供训练/加载权重的完整接口。
