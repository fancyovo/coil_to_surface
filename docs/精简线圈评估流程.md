# 精简线圈评估流程

## 1. 目的与边界

本文固定单个候选线圈的默认完整评估流程。目标是在不牺牲关键物理验收的前提下，稳定产出
score、真实磁面、Boozer $|B|$、三维 HTML、庞加莱和 DESC 结果，同时禁止把算法开发、扫参
和环境调试混入正式评估。

默认流程回答“这个线圈是否值得继续研究”；它不是精度收敛研究。10 个以上半径、多个谱阶、
超长场线积分、DESC 分辨率扫描和 100 次以上迭代都属于严格模式，只有显式要求时才运行。

## 2. 冻结原则

一次正式评估必须满足以下条件：

1. 代码、配置和模型 checkpoint 在提交前固定到 Git commit；工作区中的临时修改不得进入作业。
2. 在正式作业的第一个短阶段完成 CUDA 库加载、DESC 导入、无头绘图和 JAX device 检查；
   预检失败时不得进入任何昂贵阶段。
3. GPU 作业只有在 JAX 报告 GPU device 时才允许运行 DESC；否则改用明确的 CPU 作业，不能申请
   一张空闲 5090 后让 DESC 回退 CPU。
4. 正式作业只执行既定阶段。任何异常都记录阶段、退出码和已完成 checkpoint，然后停止；修复
   必须进入新的 debug run，不能在同一个评估目录里边调边跑。
5. 每个阶段原子写入结果，重试必须复用已完成阶段，不得重复生成磁面或长时庞加莱。

## 3. 默认算法

默认单样本物理验收只有下面这一条合法主链：

$$
\text{coils}\rightarrow\psi\rightarrow\alpha\rightarrow\nu
\rightarrow\text{受保护 Boozer 外层面}\rightarrow
\{\text{庞加莱},\ |B|,\ \text{HTML},\ \text{DESC}\}.
$$

旧的“从点云直接拟合曲面后进入 Boozer LS/Newton”路线只允许作为历史对照或单独的算法实验，
不得用于正式单样本验收，也不得用它生成的曲面替代 $\alpha+\nu$ 外层面。即使该旧路线返回数值收敛，
它的庞加莱图和 DESC 结果也不能用于否定 $\psi$、$\alpha+\nu$ 或候选线圈。所有下游产物必须记录
并核对上游 `boozer_guarded.npz` 的路径或 hash。

### 3.1 线圈到 $\psi$

完全复用稳定版 C++/CUDA 路线：线圈场、磁轴、$\psi$ 拟合和 native score 均不重新设计。
这一路径的生产目标仍是线圈到 score 稳定小于 10 s。

若 native score 状态不是 `ok`，默认到此停止，不为失败样本运行 $\alpha$、$\nu$ 或 DESC。

### 3.2 $\alpha$ 与 $\nu$

开始 $\alpha$ 拟合前先确定外层范围。`psi.a` 是拟合 $\psi$ 时使用的采样域半径，不等于最终磁面
的小半径；`s_edge` 才是本次 $\alpha+\nu$ 体坐标的外边界。不得把 `a=0.05` 或任意固定
`s_edge` 当成所有样本的默认最终边界。

默认采用稀疏的由内向外 continuation，而不追求严格最大值：复用稳定版已有的 $\psi$ 模型和 cheap
field-line screen，选取最大的 screen 通过层作为首个外层候选，同时保留紧邻的一个更外层候选用于
确认边界。候选依次通过磁通标定、$\alpha$、$\nu$ 和受保护 Newton；若外层失败则回退到上一完整
通过层，若外层仍通过则可再外扩一档。正式结果必须是这条连续分支上完整门控通过的最大已测面，
并同时记录最近的外侧失败点或尚未探测的上界。禁止只因近轴面容易成功就停在微管范围内。

默认使用已经验证的固定阶数，不做阶数扫描：

| 项目 | 默认值 |
|---|---:|
| $\alpha$ 阶数 $(L,M,N)$ | $(12,12,16)$ |
| $\nu$ 阶数 | 12 |
| $\nu$ 半径 | $\rho=0.5,0.8,1.0$ |
| 受保护 Newton | 只对 $\rho=1$ 必做 |

$\alpha$ 仍使用密集均匀点和线性最小二乘。$\nu$ 只计算三个代表半径，用于确认内、中、外层趋势；
外层面经过受保护 Newton 后成为后续所有图和 DESC 的唯一边界来源。

默认接受条件为：磁通标定单调；$1+\lambda_\theta>0$；$1+\partial_\phi\nu>0$；外层离网格
Boozer residual 和法向场 P95 均不高于 $10^{-4}$；Newton 位移 P95 不超过小半径的 5%。任一
条件失败即停止，不能继续用 DESC 的优化器掩盖上游错误。

### 3.3 默认图形验收

固定产物如下：

- Boozer $|B|$ PNG 和 HTML；
- 完整设备线圈加完整周期磁面 PNG 和 HTML；
- 快速庞加莱：8 条场线，$t_{\max}=2\times10^7$；
- 外层面、磁通、$\iota$、$G$ 和离网格 residual 的 JSON 摘要。

16 条场线、$t_{\max}=10^8$ 或更长只属于严格模式。已有相同 surface hash 的庞加莱结果必须
复用，不得因生成 HTML 而再次追踪。

### 3.4 DESC

DESC 使用同一个受保护外层面、真实线圈场积分的环向磁通、零压强和零环向电流。默认设置为
$L=M=N=8$、最多 50 次迭代；达到下列条件即可作为默认评估结果：

- `nested_initial=true` 且 `nested_final=true`；
- 最终平均归一化力误差不高于 $10^{-2}$；
- 边界误差保持在数值精度范围；
- 输出中明确区分优化器收敛和达到迭代上限。

固定 DESC 产物包括 boundary、Boozer $|B|$、$B_{M,N}(\rho)$、QA/QH/QP 误差分量、
$\iota(\rho)$、输入文件、summary 和 equilibrium。100 次以上迭代、分辨率扫描或继续求解属于
严格模式。

## 4. 资源调度

单候选不应为了“用满四卡”而制造通信和初始化开销。正确策略是按算子并行：

| 阶段 | 默认资源 | 要求 |
|---|---|---|
| native score、$\psi$、$\alpha$ | 1 GPU + 4 CPU | C++/CUDA 或 GPU LS |
| 三个 $\rho$ 的 $\nu$ | 1 GPU + 4 CPU | 合并右端，缓存同一设计矩阵/QR |
| 快速庞加莱 | 8--16 CPU | 与 DESC/绘图并行，不占 GPU |
| $|B|$ 与 HTML | 1 GPU 或复用已有场值 | 禁止重复 Biot--Savart |
| DESC | 1 GPU + 4 CPU | 提交前必须通过 JAX GPU 预检 |

外层面完成后，庞加莱、静态/HTML 绘图和 DESC 彼此独立，应使用 Slurm dependency 分成并行
作业。批量评估多个候选时，最多并发 4 个独立单卡候选；不把一个很小的线性问题强拆到四卡。

如果 DESC GPU 环境不可用，必须显式选择 CPU 作业并释放 GPU 配额。该降级需要写入摘要，
不能静默发生。

## 5. 时间预算

默认流程采用硬上限而不是无界等待：

| 阶段 | 目标墙钟 | 硬上限 |
|---|---:|---:|
| 稳定版线圈到 score | 10 s | 20 s |
| 固定阶 $\alpha$ | 90 s | 180 s |
| 三半径固定阶 $\nu$ | 90 s | 180 s |
| 外层受保护 Newton | 60 s | 120 s |
| 快速庞加莱与图形 | 40 s | 90 s |
| DESC 50 次及出图 | 180 s | 600 s |
| **完整默认评估** | **约 5--8 min** | **15 min** |

这些是下一轮优化后的验收预算，不是已经完成的 benchmark。任一阶段触及硬上限就停止并报告，
不能在正式评估中临时增加阶数、采样数或迭代数。第一次按本规范运行后必须用真实计时更新本表。

## 6. 固定执行方式

从稳定版 $\psi$ 结果开始时，必须先运行固定参数的 $\alpha+\nu$ 阶段：

```bash
sbatch --test-only scripts/slurm_alpha_nu_guarded_boozer.sh
sbatch \
  --export=ALL,PROJECT=/absolute/project/path,CASE_FILE=/path/to/case.json,RUN_DIR=/path/to/a_0p05,OUTPUT_DIR=/path/to/alpha_nu_eval \
  scripts/slurm_alpha_nu_guarded_boozer.sh
```

该作业的唯一正式外层面输出为
`/path/to/alpha_nu_eval/guarded_rho_1/boozer_guarded.npz`。只有该文件通过 $\psi$ 距离、离网格
Boozer residual、法向场、坐标单调性和 Newton 位移门槛后，才允许启动下游评估。

已有受保护 Boozer 外层面时，使用：

```bash
sbatch --test-only scripts/slurm_evaluate_saved_boozer_full.sh
sbatch --export=ALL,CASE_FILE=/path/to/case.json,SURFACE_NPZ=/path/to/boozer_guarded.npz,OUTPUT_DIR=/path/to/new_run scripts/slurm_evaluate_saved_boozer_full.sh
```

脚本默认要求 DESC GPU、快速庞加莱和 DESC 50 次迭代。严格模式必须在提交时显式覆盖：

```bash
sbatch \
  --export=ALL,CASE_FILE=/path/to/case.json,SURFACE_NPZ=/path/to/boozer_guarded.npz,OUTPUT_DIR=/path/to/new_run,POINCARE_NFIELDLINES=16,POINCARE_TMAX=1e8,DESC_MAXITER=100 \
  scripts/slurm_evaluate_saved_boozer_full.sh
```

禁止复用已有 `full_summary.json` 的完成目录。失败重试只能在程序确认 surface 一致时复用
`progress.json`，并必须跳过已经成功的可视化阶段。

禁止把稳定版 score 目录中的旧 `best_surface` 或旧 LS/Newton 曲面直接传给上述完整评估脚本。
`SURFACE_NPZ` 必须来自本节第一步的 `guarded_rho_1/boozer_guarded.npz`，或者来自已经逐项通过同等
$\alpha+\nu$ 验收且具有可追溯 hash 的历史产物。

## 7. 本次慢速复盘

本次接近两小时的交互墙钟并不来自一次固定评估，而是下列工作串行叠加：

| 原因 | 已测时间或影响 |
|---|---:|
| 先跑旧 LS/Newton/DESC 路径，最后被庞加莱否决 | 9 min 26 s |
| 正确 $\alpha+\nu$ 作业混入 4 档 $\alpha$、30 档 $\nu$ 和三半径 Newton | 22 min 54 s |
| 完整绘图再次重复长时庞加莱 | 285.1 s |
| 未预检 `tkinter`，昂贵绘图后才失败并重提 | 浪费 5 min 14 s |
| DESC 的 JAX 静默回退 CPU，5090 基本空闲 | DESC 阶段 458.3 s |
| 调试、同步、人工检查和 SSH 故障均夹在正式流程中 | 形成额外串行墙钟 |

其中可直接避免的是旧路径、开发期扫参、重复庞加莱和延迟环境报错；可优化的是曲面拟合缓存、
GPU 批量场评估和 DESC GPU 环境。今后正式评估只允许使用第 3 节的固定参数，任何方法探索都在
另一个 run 和另一个任务中进行。

## 8. 交付清单

默认评估结束前必须一次性交付：

1. 总结报告和原始 `summary.json`；
2. score 及所有分项、$\psi$/$\alpha$/$\nu$/Newton 的关键误差和计时；
3. Boozer $|B|$ PNG/HTML、线圈加磁面 PNG/HTML、快速庞加莱；
4. DESC boundary、Boozer $|B|$、$B_{M,N}(\rho)$、QA/QH/QP、$\iota(\rho)$；
5. DESC 输入、equilibrium、嵌套性、力残差、停止原因和各阶段耗时；
6. GPU/CPU 型号、JAX backend、运行前后 GPU 状态和 Git commit。
