# 精简线圈评估流程

## 1. 目的与边界

本文固定单个候选线圈的默认完整评估流程。目标是在不牺牲关键物理验收的前提下，稳定产出
score、真实磁面、Boozer $|B|$、三维 HTML、庞加莱和 DESC 结果，同时禁止把算法开发、扫参
和环境调试混入正式评估。

默认流程回答“这个线圈是否值得继续研究”；它不是精度收敛研究。10 个以上半径、多个谱阶、
超长场线积分、DESC 分辨率扫描和 100 次以上迭代都属于严格模式，只有显式要求时才运行。

## 2. 冻结原则

一次正式评估必须满足以下条件：

1. 代码、配置和模型 checkpoint 在提交前固定到 Git commit；工作区中的临时修改不得进入作业。
2. 在正式作业的第一个短阶段完成 CUDA 库加载、DESC 导入、无头绘图和 JAX device 检查；
   预检失败时不得进入任何昂贵阶段。
3. GPU 作业只有在 JAX 报告 GPU device 时才允许运行 DESC；否则改用明确的 CPU 作业，不能申请
   一张空闲 5090 后让 DESC 回退 CPU。
4. 正式作业只执行既定阶段。任何异常都记录阶段、退出码和已完成 checkpoint，然后停止；修复
   必须进入新的 debug run，不能在同一个评估目录里边调边跑。
5. 每个阶段原子写入结果，重试必须复用已完成阶段，不得重复生成磁面或长时庞加莱。
6. 申请 GPU 不等于使用 GPU。alpha、nu 和 guarded summary 必须逐项记录 backend、精度和计时；
   只有程序内 backend 记录与作业可见设备一致时才可写“GPU 执行”。单独的 `nvidia-smi` pre/post
   文件不能作为中间算子使用 GPU 的证据。

## 3. 默认算法

默认单样本物理验收只有下面这一条合法主链：

$$
\text{coils}\rightarrow\psi\rightarrow\alpha\rightarrow\nu
\rightarrow\text{受保护 Boozer 外层面}\rightarrow
\{\text{庞加莱},\ |B|,\ \text{HTML},\ \text{DESC}\}.
$$

旧的“从点云直接拟合曲面后进入 Boozer LS/Newton”路线只允许作为历史对照或单独的算法实验，
不得用于正式单样本验收，也不得用它生成的曲面替代 $\alpha+\nu$ 外层面。即使该旧路线返回数值收敛，
它的庞加莱图和 DESC 结果也不能用于否定 $\psi$、$\alpha+\nu$ 或候选线圈。所有下游产物必须记录
并核对上游 `boozer_guarded.npz` 的路径或 hash。

### 3.1 线圈到 $\psi$

完全复用稳定版 C++/CUDA 路线：线圈场、磁轴、$\psi$ 拟合和 native score 均不重新设计。
这一路径的生产目标仍是线圈到 score 稳定小于 10 s。

若 native score 状态不是 `ok`，默认到此停止，不为失败样本运行 $\alpha$、$\nu$ 或 DESC。

### 3.2 $\alpha$ 与 $\nu$

开始 $\alpha$ 拟合前先确定外层范围。`psi.a` 是拟合 $\psi$ 时使用的采样域半径，不等于最终磁面
的小半径；`s_edge` 才是本次 $\alpha+\nu$ 体坐标的外边界。不得把 `a=0.05` 或任意固定
`s_edge` 当成所有样本的默认最终边界。

默认采用稀疏的由内向外 continuation，而不追求严格最大值：复用稳定版已有的 $\psi$ 模型和 cheap
field-line screen，选取最大的 screen 通过层作为首个外层候选，同时保留紧邻的一个更外层候选用于
确认边界。候选依次通过磁通标定、$\alpha$、$\nu$ 和受保护 Newton；若外层失败则回退到上一完整
通过层，若外层仍通过则可再外扩一档。正式结果必须是这条连续分支上完整门控通过的最大已测面，
并同时记录最近的外侧失败点或尚未探测的上界。禁止只因近轴面容易成功就停在微管范围内。

默认使用已经验证的固定阶数，不做阶数扫描：

| 项目 | 默认值 |
|---|---:|
| $\alpha$ 阶数 $(L,M,N)$ | $(12,12,16)$ |
| $\nu$ 阶数 | 12 |
| $\nu$ 半径 | $\rho=0.5,0.8,1.0$ |
| 受保护 Newton | 只对 $\rho=1$ 必做 |

$\alpha$ 仍使用密集均匀点和线性最小二乘。$\nu$ 只计算三个代表半径，用于确认内、中、外层趋势；
外层面经过受保护 Newton 后成为后续所有图和 DESC 的唯一边界来源。

正式 backend 要求如下：磁通标定、alpha 的高密度场采样与 FP32 QR、psi 等值面提取、nu
训练/验证场采样以及 guarded 线搜索中的密集场验收必须使用 C++/CUDA 或 CUDA QR，并在 summary 中
显式记录。alpha+nu 只用于构造稳定初值，因此场采样、设计矩阵和 QR 默认使用 FP32；最终门控仍以
$10^{-4}$ 的物理 residual 为准。当前 nu 的 modewise 正交投影约 0.11 s/半径，保留 NumPy CPU
不会形成长尾；Simsopt
曲面拟合/重参数化和需要空间导数的 Boozer Newton 也暂时显式使用 CPU。任何 CPU 子阶段一旦单候选
超过 2 s，必须在计时表中单列，不能笼统并入“nu 耗时”，并应优先做缓存、批处理或 GPU 化。

默认接受条件为：磁通标定单调；$1+\lambda_\theta>0$；$1+\partial_\phi\nu>0$；外层离网格
Boozer residual 和法向场 P95 均不高于 $10^{-4}$；Newton 位移 P95 不超过小半径的 5%。任一
条件失败即停止，不能继续用 DESC 的优化器掩盖上游错误。
通过全部门槛时才允许生成 `boozer_guarded.npz`；失败候选必须改写为 `boozer_rejected.npz`，保留
summary 后以非零退出码停止，防止下游脚本仅凭文件存在误用失败面。

### 3.3 默认图形验收

固定产物如下：

- Boozer $|B|$ PNG 和 HTML；PNG 固定使用白底彩色等高线，颜色表示
  $|B|$ 大小，禁止用热力图或填色等高线替代；
- 完整设备线圈加完整周期磁面 PNG 和 HTML；
- 快速庞加莱：8 条场线，$t_{\max}=2\times10^7$；
- 外层面、磁通、$\iota$、$G$ 和离网格 residual 的 JSON 摘要。

16 条场线、$t_{\max}=10^8$ 或更长只属于严格模式。已有相同 surface hash 的庞加莱结果必须
复用，不得因生成 HTML 而再次追踪。

### 3.4 DESC

DESC 使用同一个受保护外层面、真实线圈场积分的环向磁通、零压强和零环向电流。默认设置为
$L=M=N=8$、最多 50 次迭代；达到下列条件即可作为默认评估结果：

- `nested_initial=true` 且 `nested_final=true`；
- 最终平均归一化力误差不高于 $10^{-2}$；
- 边界误差保持在数值精度范围；
- 输出中明确区分优化器收敛和达到迭代上限。

正式报告必须逐张内嵌下面 5 张核心 DESC 图，不能只生成文件或只在原始产物列表中给链接：

1. 最终 boundary；
2. Boozer $|B|$ 白底彩色等高线图，等高线颜色表示 $|B|$ 大小；
3. $B_{M,N}(\rho)$ 模谱；
4. 目标 helicity 的 QS 误差分量，本项目 QH 评估即为 QH 图；
5. $\iota(\rho)$。

此外，DESC `summary.json` 中所有 `success=true` 的图也必须逐张进入报告。当前标准脚本还会生成
初始 boundary 和 QA/QP 对照图，因此一次 QH 评估通常需要引用 8 张 DESC PNG。不能用“不是核心图”
为理由遗漏已经成功生成的图。报告完成前必须运行第 8 节的自动清单检查；缺图时评估状态仍为
`incomplete`。输入文件、summary 和 equilibrium 也必须作为可点击原始产物交付。100 次以上迭代、
分辨率扫描或继续求解属于严格模式。

## 4. 资源调度

单候选不应为了“用满四卡”而制造通信和初始化开销。正确策略是按算子并行：

| 阶段 | 默认资源 | 要求 |
|---|---|---|
| native score、$\psi$、$\alpha$ | 1 GPU + 4 CPU | C++/CUDA 或 GPU LS |
| 三个 $\rho$ 的 $\nu$ | 1 GPU + 4 CPU | 场采样必须 CUDA；小型正交投影可 CPU；曲面拟合逐项计时 |
| 快速庞加莱 | 8--16 CPU | 与 DESC/绘图并行，不占 GPU |
| $|B|$ 与 HTML | 1 GPU 或复用已有场值 | 禁止重复 Biot--Savart |
| DESC | 1 GPU + 4 CPU | 提交前必须通过 JAX GPU 预检 |

外层面完成后，庞加莱、静态/HTML 绘图和 DESC 彼此独立，应使用 Slurm dependency 分成并行
作业。批量评估多个候选时，最多并发 4 个独立单卡候选；不把一个很小的线性问题强拆到四卡。

如果 DESC GPU 环境不可用，必须显式选择 CPU 作业并释放 GPU 配额。该降级需要写入摘要，
不能静默发生。

## 5. 时间预算

默认流程采用硬上限而不是无界等待：

| 阶段 | 目标墙钟 | 硬上限 |
|---|---:|---:|
| 稳定版线圈到 score | 10 s | 20 s |
| 固定阶 $\alpha$ | 90 s | 180 s |
| 三半径固定阶 $\nu$ | 90 s | 180 s |
| 外层受保护 Newton | 60 s | 120 s |
| 快速庞加莱与图形 | 40 s | 90 s |
| DESC 50 次及出图 | 180 s | 600 s |
| **完整默认评估** | **约 5--8 min** | **15 min** |

任一阶段触及硬上限就停止并报告，不能在正式评估中临时增加阶数、采样数或迭代数。

2026-07-30 在一张空闲 RTX 5090 和 16 CPU 上对 `a=0.08, s_edge=0.20` 的正确链路实测为：固定阶
$\alpha$ 147.1 s，三半径 $\nu$ 86.1 s，包含受保护 Newton、初始化和清理的 alpha+nu 作业
311 s；8 线庞加莱与静态/HTML 33.0 s；16 核 CPU DESC 及出图 321.7 s，下游完整作业
407.6 s。已知候选范围后的完整串行墙钟约 12 min，低于 15 min 硬上限，但尚未达到 5--8 min
目标。当前优先优化 DESC、磁通标定和曲面重参数化；QR solve 实测仅约 7.0 s，不是瓶颈。

同日将初值链路改为 FP32 后，使用相同采样规模和 `s_edge=0.20` 的完整 smoke 为 5 min 00 s；
相邻 FP64 smoke 为 5 min 35 s。alpha QR 从 6.931 s 降至 1.911 s，最终 guarded relative $L^2$
为 $4.41974\times10^{-5}$，法向场 P95 为 $5.71595\times10^{-5}$，全部绝对门槛保持通过。
因此生产默认使用 FP32，但每次仍必须以物理 residual 门控，不能只以 dtype 推断精度足够。

## 6. 固定执行方式

从稳定版 $\psi$ 结果开始时，必须先运行固定参数的 $\alpha+\nu$ 阶段：

```bash
sbatch --test-only scripts/slurm_alpha_nu_guarded_boozer.sh
sbatch \
  --export=ALL,PROJECT=/absolute/project/path,GPU_LIB=/path/to/libstellarator_gpu.so,CASE_FILE=/path/to/case.json,RUN_DIR=/path/to/selected_psi_run,S_EDGE=0.30,OUTPUT_DIR=/path/to/alpha_nu_eval \
  scripts/slurm_alpha_nu_guarded_boozer.sh
```

该作业的唯一正式外层面输出为
`/path/to/alpha_nu_eval/guarded_rho_1/boozer_guarded.npz`。只有该文件通过 $\psi$ 距离、离网格
Boozer residual、法向场、坐标单调性和 Newton 位移门槛后，才允许启动下游评估。

已有受保护 Boozer 外层面时，使用：

```bash
sbatch --test-only scripts/slurm_evaluate_saved_boozer_full.sh
sbatch --export=ALL,CASE_FILE=/path/to/case.json,SURFACE_NPZ=/path/to/boozer_guarded.npz,OUTPUT_DIR=/path/to/new_run scripts/slurm_evaluate_saved_boozer_full.sh
```

脚本默认要求 DESC GPU、快速庞加莱和 DESC 50 次迭代。严格模式必须在提交时显式覆盖：

```bash
sbatch \
  --export=ALL,CASE_FILE=/path/to/case.json,SURFACE_NPZ=/path/to/boozer_guarded.npz,OUTPUT_DIR=/path/to/new_run,POINCARE_NFIELDLINES=16,POINCARE_TMAX=1e8,DESC_MAXITER=100 \
  scripts/slurm_evaluate_saved_boozer_full.sh
```

禁止复用已有 `full_summary.json` 的完成目录。失败重试只能在程序确认 surface 一致时复用
`progress.json`，并必须跳过已经成功的可视化阶段。

禁止把稳定版 score 目录中的旧 `best_surface` 或旧 LS/Newton 曲面直接传给上述完整评估脚本。
`SURFACE_NPZ` 必须来自本节第一步的 `guarded_rho_1/boozer_guarded.npz`，或者来自已经逐项通过同等
$\alpha+\nu$ 验收且具有可追溯 hash 的历史产物。

本次接近两小时的交互墙钟并不来自一次固定评估，而是下列工作串行叠加：

| 原因 | 已测时间或影响 |
|---|---:|
| 先跑旧 LS/Newton/DESC 路径，最后被庞加莱否决 | 9 min 26 s |
| 正确 $\alpha+\nu$ 作业混入 4 档 $\alpha$、30 档 $\nu$ 和三半径 Newton | 22 min 54 s |
| 完整绘图再次重复长时庞加莱 | 285.1 s |
| 未预检 `tkinter`，昂贵绘图后才失败并重提 | 浪费 5 min 14 s |
| DESC 的 JAX 静默回退 CPU，5090 基本空闲 | DESC 阶段 458.3 s |
| 调试、同步、人工检查和 SSH 故障均夹在正式流程中 | 形成额外串行墙钟 |

其中可直接避免的是旧路径、开发期扫参、重复庞加莱和延迟环境报错；可优化的是曲面拟合缓存、
GPU 批量场评估和 DESC GPU 环境。今后正式评估只允许使用第 3 节的固定参数，任何方法探索都在
另一个 run 和另一个任务中进行。

### 7.1 本次纠错暴露的全部流程问题

本次对 zeroth-order Adam 最佳样本的验收还暴露了以下问题。它们都属于流程或实现错误，不能归因于
候选线圈的物理质量。

| 问题 | 造成的后果 | 固化的预防措施 |
|---|---|---|
| 正式验收误走旧的直接 LS/Newton 曲面路线，没有先走 $\psi\rightarrow\alpha\rightarrow\nu$ | 产生散乱庞加莱和失败 DESC，并一度错误否定候选 | 第 3、6 节规定唯一合法主链；下游强制记录并核对 `boozer_guarded.npz` hash |
| 把 `a=0.05` 的近轴拟合域当成最终评估范围，没有主动寻找较大磁面 | 即使小面成功也不能说明线圈具有实用体积 | 区分 `psi.a` 和 `s_edge`；由内向外 continuation，报告最大已测通过面和最近外侧失败点 |
| guarded Newton 只看相邻步改善，没有绝对 residual 门槛，失败面仍可能写成可用文件 | 坏面能够仅凭文件存在进入庞加莱和 DESC | relative $L^2$ 与法向场 P95 均设 $10^{-4}$ 绝对门槛；失败只写 `boozer_rejected.npz` 并非零退出 |
| 看见低 $\psi$ 残差却没有先质疑下游路径和绘图，直接接受离谱庞加莱结论 | 把明显的链路矛盾误判为候选物理失败 | 报告必须做上游一致性检查；低 $\psi$ 残差与大范围散射冲突时先停止下游结论并审计 surface hash/坐标映射 |
| GPU preflight 检查节点所有 GPU，而非 Slurm 分配给作业的 `CUDA_VISIBLE_DEVICES` | 无关卡上的占用会制造假失败并干扰调度判断 | 预检只查询当前作业可见设备，评测前后均记录同一设备 |
| alpha+nu 脚本隐含要求当前 worktree 自带 GPU 动态库 | 发生不必要的重编译、同步和环境调试 | `GPU_LIB` 显式指向已验证共享构建，并记录库 hash；源码变化后才重建 |
| 看到作业申请了 5090 就默认 alpha+nu 全程 GPU，没有审计 nu 内部 backend | 本次 nu 场评估、投影和曲面重建实际走 CPU；以后扩大采样或阶数时可能再次出现长尾 | 每个子阶段写 backend/精度/计时；高密度场评估强制 CUDA；CPU 超过 2 s 必须单列和优化 |
| 庞加莱候选边界的截面首尾未闭合 | 图中出现跨周期错误连线和视觉接缝 | 绘图代码显式闭合每个独立截面；不同场周期之间禁止直接连线 |
| 正式运行、方法扫参、环境修复和重绘混在同一验收过程 | 墙钟膨胀，结果目录难以审计 | 正式 run 固定 commit/参数且失败即停；所有调试进入独立目录和独立作业 |
| DESC 已生成完整诊断图，但报告只引用 3 张，遗漏 Boozer 场、模谱及对照通道 | 读者无法完成结果验收，交付不完整 | 第 3.4 节规定核心 5 图和全部成功图逐张引用；第 8 节自动检查不通过时不得交付 |

## 8. 交付清单

默认评估结束前必须一次性交付：

1. 总结报告和原始 `summary.json`；
2. score 及所有分项、$\psi$/$\alpha$/$\nu$/Newton 的关键误差和计时；
3. Boozer $|B|$ 白底彩色等高线 PNG/HTML、线圈加磁面 PNG/HTML、快速庞加莱；
4. 报告中逐张内嵌 DESC 核心 5 图，并逐张内嵌 `summary.json` 里其余所有成功图；
5. DESC 输入、equilibrium、嵌套性、力残差、停止原因和各阶段耗时；
6. GPU/CPU 型号、JAX backend、alpha/nu/guarded 每个子阶段的 backend/精度/计时、运行前后 GPU 状态和 Git commit。

报告提交前必须执行：

```bash
python scripts/validate_desc_report_artifacts.py \
  --report reports/<report>.md \
  --desc-dir reports/assets/<case>/desc \
  --target-helicity QH
```

该命令同时检查核心 5 图、`summary.json` 中所有成功图、DESC 目录内全部 PNG 及其在报告中的精确
相对路径引用。退出码非零表示交付不完整，不能把评估标记为完成。

## 9. 固定代码入口

完整评估所需的提交、选面、下游和交付校验入口统一位于：

```text
evaluation/full_physical/
```

该目录中的 `README.md` 是唯一操作说明，`code_manifest.json` 给出每个阶段对应的唯一底层实现。
两个提交入口会自动执行 `preflight.py` 和 `sbatch --test-only`，在占用算力前检查代码清单、Python/Shell
语法及 Slurm 参数。
正式评估只允许依次使用以下入口，不能临时复制或拼装另一套脚本：

1. `submit_surface_candidates.sh`：串行稀疏外扩候选，默认任意时刻最多使用一张 GPU；
2. `select_largest_guarded_surface.py`：选择最大已测通过面，并默认要求存在更外侧失败点；
3. `submit_downstream.sh`：显式选择 CPU 或 GPU DESC 后提交完整下游；
4. `validate_delivery.sh`：检查固定产物和报告内全部 DESC 图引用。

底层物理代码仍位于 `scripts/` 和 `stellarator_eval/`，入口目录只做编排与校验，不复制实现。
这样修正物理代码后只有一个生效版本，也避免下次评估重新调试提交参数、选面规则和交付清单。
