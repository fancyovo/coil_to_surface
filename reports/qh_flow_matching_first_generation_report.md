## 1. 结论先行

本轮已经跑通“QUASR QH 线圈数据 -> 无条件 flow matching -> 生成线圈 -> 原生
C++/CUDA score”的第一代闭环。旧服务器只用于从只读 QUASR 源数据中提取线圈，训练和
评测全部在新服务器完成。

目前可以确认：

1. 全部 170,755 个 QH 样本均成功提取，0 失败；新旧两端的分片哈希一致，100 个随机样本
   与原始 JSON 逐 FP32 token 完全一致。
2. 30,333,540 参数的非因果 Llama 风格 flow 模型可以稳定用 4 卡 BF16/DDP 训练；8,000
   step 总墙钟为 16 分 54 秒，没有 NaN、OOM 或训练长尾。
3. 正式生成的 2,048 个样本全部有限，99.3% 通过廉价几何门，718 个（35.1%）能走完
   原生 C++/CUDA score，说明模型不只学会了表面几何外形。
4. 但第一代模型没有复现训练数据的物理质量：成功样本 score 中位数为 48.34，最高 63.61；
   QUASR 参考集中成功 QH 的中位数为 66.83。2,048 个生成样本中没有一个达到该门槛。
5. 因此本轮没有启动拒绝采样再训练。当前 checkpoint 可用于诊断，但不适合作为“从生成
   elite 自举”的起点；直接取它的 top 样本回灌，训练目标反而低于原始 QH 数据。
6. QH 相对 QA/QP 的竞争优势尚未写入 reward。它仍然是下一代 reward 的必要部分，但眼下
   更优先的问题是让基础 flow 首先学回 QUASR QH 本身的联合分布。

## 2. 数据如何得到

### 2.1 只迁移需要的线圈数据

旧服务器上的源目录 `/data/zhouyebi/QUASR_08072024/` 全程只读。提取器直接解析 SIMSON
JSON 图，不依赖 Simsopt：

1. 从 metadata 选择所有 `helicity=1` 记录。
2. 在 SIMSON graph 中只选择直接使用 `CurveXYZFourier` 的基线线圈，排除由对称操作生成的

$$
\boldsymbol c_j=
[\boldsymbol x_j^{(33)},\boldsymbol y_j^{(33)},
\boldsymbol z_j^{(33)},I_j]\in\mathbb R^{100}.
$$

最终数据只占 224,204,485 字节，共 44 个 NPZ 分片；没有复制完整的 80+ GB QUASR。

## 3. 模型与训练目标

### 3.1 线圈集合表示

一个样本包含 $n_c$ 个线圈 token，形状为 $n_c\times100$。线圈顺序没有物理意义，因此：

- 不使用 RoPE 或任何位置编码；
- attention 非因果、全连接；
- 训练时随机置换 token 顺序；
- 单元测试验证模型对线圈置换等变。

电流先按 $(N_{\mathrm{FP}},n_c)$ 组固定总绝对电流：

$$
I_j\leftarrow I_j
\frac{I_{\mathrm{ref}}(N_{\mathrm{FP}},n_c)}{\sum_k|I_k|},
$$

其中 $I_{\mathrm{ref}}$ 是训练组的中位数。再把绝对值最大的电流固定为正，去掉整体电流符号
和尺度两条不必要的自由度。每个特征只用训练集统计量标准化，并裁剪到 $[-8,8]$。

### 3.2 网络

模型是 8 层、宽度 512、8 头、SwiGLU hidden 1408 的非因果 Transformer：

- 30,333,540 个参数；
- RMSNorm、PreNorm、SwiGLU；
- 无 RoPE、无因果 mask、无 dropout；
- 每个 block 注入 flow 时间 embedding 和 learned $N_{\mathrm{FP}}$ embedding；
- 除 $N_{\mathrm{FP}}$ 外，不输入 score、QS、$\iota$、线圈数或其他条件。

线圈数由噪声张量第一维自然给出，模型可以处理训练数据中出现过的
$(N_{\mathrm{FP}},n_c)$ 组合。

### 3.3 Rectified flow

对标准化数据 $\boldsymbol x_1$ 和同形状高斯噪声
$\boldsymbol x_0\sim\mathcal N(0,I)$，使用线性路径：

$$
\boldsymbol x_t=(1-t)\boldsymbol x_0+t\boldsymbol x_1,
\qquad t\sim\mathcal U(0,1),
$$

目标速度为：

$$
\boldsymbol v^*=\boldsymbol x_1-\boldsymbol x_0.
$$

训练目标是全部 token 和特征上的均方误差：

$$
\mathcal L_{\mathrm{FM}}=
\mathbb E\left[
\left\|\boldsymbol v_\theta(\boldsymbol x_t,t,N_{\mathrm{FP}})
-\boldsymbol v^*\right\|_2^2
\right].
$$

生成时从 $t=0$ 的高斯噪声出发，用 Heun 法积分到 $t=1$。训练监控用 16 步，正式评测
用 32 步。

## 7. 开发中发现并修复的问题

### 7.1 `torchrun` 不在计算节点 PATH

首个 pilot `28417` 在确认四卡空闲后立即退出，错误为 `torchrun: command not found`。
入口统一改为：

`python -m torch.distributed.run`

这不改变 DDP 语义，并消除了对用户脚本 PATH 的依赖。

### 7.2 训练内多进程 score 与 DDP 冲突

第一次正式训练 `28426` 在 step 2000 让 rank 0 创建四个额外 CUDA 评分子进程，而另外三个
rank 停在 NCCL barrier，形成等待。该作业被主动取消，没有留下进程。

修复后由四个现有 DDP rank 各自在本地 GPU 上评分索引 `rank::4` 的候选，再由 rank 0 汇总。
8 样本 smoke `28446` 在 7.67 秒内完成，正式训练的四次监控均正常退出。

### 7.3 原生库动态链接路径

PyTorch wheel 自带 CUDA 13 运行库，但原生 score 的 `libstellarator_gpu.so` 初次加载时找不到
`libcusolver.so.12`。Slurm 入口现在由 `torch.__file__` 动态推导
`nvidia/cu13/lib`，验证文件存在后加入 `LD_LIBRARY_PATH`，不硬编码 Python 小版本。

### 7.4 NCCL 设备绑定

`init_process_group` 和 barrier 现在都显式绑定 `LOCAL_RANK` 对应设备，消除了 PyTorch
“猜测 barrier device”的警告，也避免多节点扩展时潜在的 rank/device 错配。

## 8. 为什么第一代没有学回物理质量

当前证据可以排除数据传输错误、明显几何崩坏、GPU 训练不稳定和 score 链路故障。最值得
优先检查的是无序线圈集合的 flow coupling：

1. 一个物理线圈集合有 $n_c!$ 个等价 token 排列。当前训练每次随机置换数据 token，但高斯
   噪声 token 与数据 token 仍按索引做独立线性配对。模型虽然在结构上置换等变，训练路径却
   同时包含所有排列对应的多模态速度；条件平均会模糊必须由多根线圈共同维持的精细相关性。
2. 几何门只约束单根曲线是否有限、平滑、不过度弯曲。它无法检查多根线圈合成后是否有正确
   磁轴、磁面和 QH，因此 99.3% 的几何通过率不能代表物理分布拟合成功。
3. 验证 loss 到 step 8,000 仍为 1.017，且最后阶段下降已经较慢。继续简单增加训练步数可能
   有改善，但现有物理差距过大，不能假设只靠更久训练就会消失。
4. 32 步 Heun 已比训练监控的 16 步更保守；8 步 smoke 也能得到相近量级结果。积分步数不是
   当前 25 倍 QS residual 差距的首要解释，但仍应做同噪声的 32/64 步收敛检查。

## 9. 下一步建议

当前不应直接启动只使用生成 elite 的拒绝采样。建议按以下顺序推进：

1. **修正集合配对。** 对每个噪声集合与目标线圈集合做最小代价匹配，或采用 minibatch OT
   flow matching，使训练路径不再为任意 token 排列付出多模态平均代价。也可以先用确定性的
   线圈规范排序做低成本对照实验。
2. **做小规模归因实验。** 固定同一批噪声，比较 32/64 步 Heun；分别评测 step 6000 和
   step 8000；统计训练数据最近邻和生成去重。每项只需数百样本，不必再跑 2,048 个全评测。
3. **恢复基础分布后再加 reward。** 当生成 `ok` 率和 score 分位数接近 held-out QUASR QH
   后，再加入同一点集上的 $e_{\mathrm{QH}}$ 相对 $e_{\mathrm{QA}},e_{\mathrm{QP}}$ margin，冻结
   score 版本，然后做按 $(N_{\mathrm{FP}},n_c)$ 分组的拒绝采样。
4. **避免低质自举。** 若改进后的生成分布仍达不到参考中位数，第二代训练应把原始高质量
   QUASR QH 与生成 top 样本混合，而不是只保留当前生成 top；否则 replay 会把分布向更差的
   score 移动。

最终判断是：第一代工程链路和速度目标已验证，但“第一代生成结果中包含一定比例较好 QH”
这一物理验收标准没有通过。下一步的核心不是扩大拒绝采样规模，而是先消除无序集合 flow
配对造成的联合分布模糊，并用同版原生 score 重新验收。
