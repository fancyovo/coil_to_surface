# 01 扰动鲁棒性检查

## 实验设置

- 基准样例：`examples/01.json`, key=`raw`
- 扰动方式：对线圈几何系数 `x/y/z` 全部分量独立施加乘性高斯扰动：
  $$
  c \leftarrow c + c \varepsilon,\qquad \varepsilon \sim \mathcal N(0, \text{level}^2)
  $$
- 扰动强度：`1e-3, 2e-3, 5e-3, 1e-2, 2e-2, 5e-2, 1e-1, 2e-1, 3e-1`
- 每个 level 取 `8` 个随机种子，共 `72` 次评估
- 评估配置：当前默认 GPU 主流程，额外指定 `initial_iota=-2.9`
- 单次超时上限：`40 s`

实验产物在 [runs/robustness_01_perturb_main_fixed_remote](D:/Typora/Typ/学习/stellarator/programs/local_surface_evaluator/runs/robustness_01_perturb_main_fixed_remote)。

## 主要结论

1. 没有出现超时。即使扰动到 `0.3`，所有样本也都在 `5.6 s` 内结束。
2. 真正的坏样本会更快返回，而不是更慢：
   - `surface`：中位总时间约 `3.0 s`
   - `no_surface`：约 `2.6 s`
   - `no_axis`：约 `2.2 s`
3. `level <= 0.02` 时，`8/8` 都能找到可用磁面。
4. 从 `level=0.05` 开始出现失败；到 `level=0.3` 时，主导失败模式已经变成 `no_axis`。
5. 高扰动下总时间下降，主要原因不是单次计算更快，而是更多样本在前面阶段提前退出。

## 本次修补的鲁棒性问题

原始版本在高扰动样本上暴露出一个明确缺陷：

- GPU 遗传算法给出一个看起来残差很小的候选点后，`trace_axis(...)` 的自适应积分可能失败，并抛出：
  `RuntimeError: axis trace failed: Required step size is less than spacing between numbers.`
- 这类样本本质上应该视为“没有可靠磁轴”，而不是整条流程崩掉。

已做两处修补：

1. [stellarator_eval/axis.py](D:/Typora/Typ/学习/stellarator/programs/local_surface_evaluator/stellarator_eval/axis.py)
   - 当 `best_residual > tol` 时，不再额外做 `trace_axis`
   - 当 `trace_axis` 失败时，直接回退成 `has_axis=False`，并保留 `trace_error`
2. [stellarator_eval/pipeline.py](D:/Typora/Typ/学习/stellarator/programs/local_surface_evaluator/stellarator_eval/pipeline.py)
   - 所有提前返回路径都统一写出 `timing` 字段

修补后，原先的 `crash` 样本全部收敛为 `no_axis`，并保持快速返回。

## `no_axis` 时返回什么

当前约定是：

- `axis.has_axis = false` 只表示“没有通过磁轴判定”
- 但 `axis.best_residual` 仍然返回“搜索过程中找到的最好闭合残差”
- 这个残差的定义写在返回结构里：
  `axis.best_residual_definition = "closure distance after tracing one field period from the best candidate"`

也就是说，`no_axis` 不是“不返回数值”，而是：

1. 给出最好的候选点 `best_R, best_Z`
2. 给出该候选点绕一个周期后的起终点距离 `best_residual`
3. 用 `has_axis` / `failure_reason` 说明它为什么没有被接受成“磁轴”

额外说明：

- `failure_reason = residual_above_tol`：最好残差仍然大于阈值
- `failure_reason = trace_failed`：残差虽然看起来够小，但后续高精度轴线追踪失败，因此不接受

对于 GPU 路径，还额外保留：

- `axis.search_best_residual`：搜索阶段内部使用的最优残差
- `axis.best_residual`：最终用于判定和输出的最优残差

通常这两个值一样；只有 GPU 搜索末尾做了更高精度复核时，它们才可能不同。
