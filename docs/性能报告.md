# 性能报告

本文档给出 `local_surface_evaluator` 当前主线实现的细粒度性能结果。重点是：

- 每个阶段到底花了多少时间；
- 真正的瓶颈在哪里；
- GPU 化之后瓶颈发生了什么变化。

## 1. 统计口径

本文所有时间默认取自程序输出的 `summary.json`。

需要注意：

1. `summary.json` 中的 `total_time_s` 是程序内部主流程计时，不包含 Python 解释器启动、模块导入、shell 包装等额外开销。
2. 因此命令行看到的总墙钟时间通常会略大于 `summary.json`。
3. 下文的“阶段耗时”都是互相可加的主流程分段，不再重复计数。

本次文档修订后，`boozer_candidates_s` 的口径已经修正，不再重复叠加 `extract_surface_time_s`。

还有一点需要单独说明：

- 用户如果追问“纯粹算 $B$ 阵列到底花了多久”，当前 `fullgpu` 路径没有把这个时间单独暴露成 summary 字段。
- 原因不是漏记，而是现在的实现把 $B$ 采样、局部坐标准备、幂表准备和部分基函数准备放在同一批 GPU 流程里。
- 因此当前代码能稳定给出的最细拆分是：
  - `assemble_basis_s`
  - `assemble_normal_eq_s`
- 其中 `assemble_basis_s` 不能直接解释成“纯 $B$ 采样时间”。

## 2. 测试环境

测试在远端服务器上完成，使用当前主线代码与 GPU 后端。

运行配置要点：

- GPU：单张 5090
- CPU 线程：`OMP_NUM_THREADS=1`
- BLAS 线程：`OPENBLAS_NUM_THREADS=16`, `MKL_NUM_THREADS=16`
- 磁力线追踪默认精度：`mixed64`
- $\psi$ 拟合后端：`fullgpu`
- 正规方程精度：`fp64`

两组基准用例：

1. `examples/01.json`, key=`raw`
2. `examples/debug.json`, key=`raw`

## 3. 01/raw 细粒度性能

### 3.1 总览

`summary.json` 记录的总时间：

$$
3.9032 \ \mathrm{s}
$$

这是当前主链路从输入磁场到输出 Boozer 面评估结果的内部计时总和。

### 3.2 主阶段拆分

| 阶段 | 时间 (s) | 说明 |
|---|---:|---|
| `field_build_s` | 0.0163 | 构造磁场对象 |
| `axis_s` | 1.0462 | 磁轴搜索 + 磁轴曲线追踪 |
| `psi_fit_s` | 1.4337 | $\psi$ 拟合全流程 |
| `surface_screen_s` | 0.4019 | 候选 `psi_0` 快速筛选 |
| `boozer_candidates_s` | 1.0043 | 等值面提取 + 曲面拟合 + LS/Newton/QS |

可以直接看到，当前最大的三块是：

1. `psi_fit_s`
2. `axis_s`
3. `boozer_candidates_s`

### 3.3 磁轴阶段拆分

| 子阶段 | 时间 (s) |
|---|---:|
| `axis_search_s` | 0.6508 |
| `axis_trace_s` | 0.0225 |
| 其余组织与收尾 | 0.3729 |

结果：

- 最优残差：`1.73698e-08`

结论：

- 真正的大头是遗传式搜索本身。
- 追踪出整条磁轴只占很小一部分。

### 3.4 $\psi$ 拟合阶段拆分

| 子阶段 | 时间 (s) | 说明 |
|---|---:|---|
| `gpu_create_s` | 0.0014 | GPU 后端对象创建 |
| `training_point_s` | 0.0177 | 训练点生成 |
| `assemble_s` | 1.3786 | GPU 侧组装总时间 |
| `assemble_basis_s` | 0.0736 | 基函数/导数准备 |
| `assemble_normal_eq_s` | 1.3049 | $A^T A$ 与 $A^T b$ 主耗时 |
| `solve_s` | 0.0173 | cuSOLVER 解线性系统 |
| `fullgpu_copy_in_s` | 0.00110 | CPU 到 GPU 传输 |
| `fullgpu_residual_s` | 0.00327 | GPU 侧回算残差 |
| `fullgpu_copy_out_s` | 0.000024 | GPU 到 CPU 取结果 |
| `validation_s` | 0.00875 | 验证集评估 |

拟合规模：

- 训练点数：`389440`
- 模态数：`1574`

拟合质量：

- 训练 RMS：`4.2473e-04`
- 验证角度均值：`1.7872e-05`
- 验证角度 p95：`5.5332e-05`

结论：

1. $\psi$ 拟合现在已经不是“采样 B 慢”或“解方程慢”。
2. 真正的主瓶颈是 GPU 上构造正规方程：

$$
A^T A,\quad A^T b
$$

3. 求解本身只要 `0.017 s`，已经不是主要问题。
4. 如果后续要把“纯 $B$ 阵列时间”单独列出来，需要继续给 CUDA kernel 加更细的阶段计时，不能直接拿现有 `assemble_basis_s` 代替。

### 3.5 `psi_0` 筛选阶段拆分

| 子阶段 | 时间 (s) |

## 5. 当前瓶颈排序

按当前稳定主线，瓶颈排序大致如下。

### 5.1 第一瓶颈：$\psi$ 拟合中的正规方程组装

典型耗时：

- `01/raw`：`1.3049 s`
- `debug/raw`：`1.2736 s`

这是当前整条链路里最确定、最稳定的大头。

### 5.2 第二瓶颈：磁轴搜索

典型耗时：

- `01/raw`：`0.6508 s`
- `debug/raw`：`0.8278 s`

这一步已经比早期 CPU 方案快很多，但仍然是主成本之一。

### 5.3 第三瓶颈：三维等值面提取

典型耗时：

- `01/raw`：`0.8853 s`
- `debug/raw`：`0.8569 s`

这一步本质上是大量一维 Newton 叠加，当前仍偏 CPU 风格。

### 5.4 第四瓶颈：筛选阶段的高精度复核追踪

典型耗时：

- `01/raw`：`0.2982 s`
- `debug/raw`：`0.3597 s`

它不是全链路最大块，但已经明显高于轻量级初筛追踪。

### 5.5 不是瓶颈的部分

以下部分当前已经比较轻：

- 磁场对象构造
- $\psi$ 拟合中的数据传输
- 线性系统求解
- `SurfaceXYZTensorFourier` 拟合
- Boozer Newton
- QS 计算

## 6. GPU 化后的瓶颈变化

GPU 化前，$\psi$ 拟合的大头主要体现在：

1. 大量点上的 $B$ 采样；
2. CPU 组装矩阵；
3. CPU 构造正规方程。

现在 `fullgpu` 路径把这些都搬到 GPU 后，瓶颈发生了变化：

1. $B$ 采样不再单独显眼；
2. 求解器也不再显眼；
3. 真正剩下的是 GPU 端大矩阵相关运算，尤其是：

$$
A^T A,\quad A^T b
$$

因此下一阶段优化不能再泛泛地说“继续上 GPU”，而要具体瞄准：

- 正规方程构造 kernel
- tile 设计
- 精度路径
- 是否允许分块累积

## 7. 对后续优化的建议

### 7.1 优先级最高

优先优化以下两块：

1. $\psi$ 拟合的正规方程构造
2. 三维等值面的批量一维 Newton 提取

原因很直接：它们是现在最稳定的两个大头。

### 7.2 次优先级

可以继续看：

1. 磁轴搜索中的一圈复核与群体演化细节
2. `psi_0` 筛选中的高精度复核追踪

### 7.3 暂时没必要优先动的部分

短期内不建议优先投入时间在：

1. Boozer Newton
2. QS 计算
3. 结果写盘

因为这些部分对总时间影响已经很小。

## 8. 当前结论

当前主线已经做到：

1. `01/raw` 与 `debug/raw` 两个例子都能跑通完整评估链。
2. 总耗时已经压到约 `4 s` 量级。
3. 瓶颈已经从“能不能在 GPU 上算”转变为“GPU 上哪一段矩阵运算最贵、该怎么继续拆”。

如果下一步继续做 GPU 深化，最值得盯紧的不是 Boozer 后半段，而是：

1. $\psi$ 拟合正规方程
2. 三维等值面提取

这两块决定了后续还能不能再明显往下压时间。
